# ИИ-импорт программ

Контракт `/api/v2/imports`. Решения — [ADR-0008](adr/0008-ai-program-import.md). Статус: реализовано
(этап 6). Импорт с фото не делаем.

Пользователь присылает программу текстом, ссылкой на Google Таблицу или файлом `.xlsx` / `.csv`. Сервер
задаёт уточняющие вопросы или возвращает **черновик** в формате payload `program` v1. Сервер программу
не сохраняет: клиент показывает предпросмотр и записывает черновик обычной записью
(`POST /api/v2/sync/push`), см. «Сохранение черновика».

## API

### `POST /api/v2/imports` (JSON)

```json
{ "text": "Присед 5×5 75%, жим 4×6 @8 …", "startDate": "2026-11-02", "targetOwnerId": null }
{ "url": "https://docs.google.com/spreadsheets/d/…/edit#gid=0", "startDate": "2026-11-02" }
```

Ровно одно из `text` и `url`. `startDate` — дата начала первой недели (по умолчанию сегодня по UTC).
`targetOwnerId` — подопечный, если импортирует тренер: право проверяет `AccessPolicy` (тренер с активной
связью); 1ПМ берётся подопечного.

### `POST /api/v2/imports` (multipart)

Поле `file` — `.xlsx` (распознаётся по сигнатуре) или `.csv` в UTF-8 до 1 МБ; поля `startDate`,
`targetOwnerId` — как выше.

### `POST /api/v2/imports/{id}/answers`

```json
{ "answers": [ { "questionId": "q1", "optionId": "a" }, { "questionId": "q2", "text": "своё" } ] }
```

### Ответ

```json
{ "id": "…", "status": "questions" | "draft", "round": 1,
  "questions": [ { "id": "q1", "text": "Сколько недель?", "options": [ { "id": "a", "text": "4" } ] } ],
  "draft": { "programId": "…", "program": { … payload program v1 … },
             "newExercises": [ { "id": "…", "exercise": { … payload exercise v1 … } } ] },
  "warnings": [ { "code": "new_exercise", "message": "…", "exercise": "Тяга в наклоне", "exerciseId": "…",
                  "suggestions": [ { "exerciseId": "…", "name": "Тяга штанги в наклоне" } ] } ],
  "expiresAt": "…" }
```

Предупреждения (`warnings[].code`):

| Код | Что значит |
| --- | --- |
| `new_exercise` | упражнения нет в библиотеке: в черновике оно новое своё (`exerciseId` — его id в `newExercises`), `suggestions` — похожие из библиотеки (до 3) для замены |
| `no_one_rep_max` | нет 1ПМ: вес не посчитан, процент — в заметке подхода |
| `no_top_set` | «−N% от топ-сета», но вес топ-сета неизвестен: процент — в заметке |
| `rpe_out_of_range` | RPE вне 5–10, не задан |
| `assumption` | допущение модели, которое стоит проверить |

### Сохранение черновика

Программа черновика уже ссылается на все упражнения: найденные — по id из библиотеки, не найденные — по id
из `draft.newExercises`. Клиент:

1. показывает предпросмотр; для каждого `new_exercise` даёт выбрать: создать своё или заменить на одно
   из `suggestions` — тогда заменяет `exerciseId` (и `exerciseName`) в программе и не сохраняет это новое
   упражнение;
2. сохраняет оставшиеся `newExercises` как свои упражнения (`type: exercise`, `id`, payload `exercise` v1)
   и затем программу (`type: program`, `id: draft.programId`) — можно одной пачкой `sync/push`, порядок
   внутри пачки не важен: ссылки между агрегатами без FK.

Новое упражнение — название как в программе, тип результата `weight_reps`, если в тексте есть повторы
или вес, иначе `free`; без мышц и оборудования, их пользователь допишет. Одинаковые названия (без учёта
регистра, «ё» и пробелов) — одно новое упражнение.

**Импорт тренером для подопечного.** Тренер не пишет упражнения подопечного, поэтому новые упражнения
он сохраняет как свои (без `ownerId`), а программу — с `ownerId` подопечного. При записи программы сервер
копирует его упражнения в библиотеку подопечного ([coaching.md](coaching.md), «Упражнения тренера»).

### Ошибки

Тело: `{ "error": "<код>", "message": "<текст для пользователя>" }`.

| HTTP | `error` | Когда |
| --- | --- | --- |
| 400 | `invalid_source`, `empty_input`, `input_too_long`, `file_too_large`, `too_many_cells`, `invalid_file`, `invalid_sheet_url` | вход не подходит |
| 403 | `forbidden` | импорт для чужого пользователя без активной связи тренера |
| 404 | `not_found` | сессии нет или она чужая |
| 409 | `not_awaiting_answers` | сессия не ждёт ответов (черновик готов, ошибка или ответ уже обрабатывается) |
| 410 | `expired` | сессия старше суток |
| 422 | `sheet_not_accessible` | таблица не открыта «всем, у кого есть ссылка» |
| 422 | `model_output_invalid`, `no_program`, `draft_invalid` | модель не смогла разобрать программу |
| 429 | `daily_limit`, `too_many_concurrent` | больше 20 импортов в сутки или 2 одновременно |
| 503 | `import_unavailable`, `import_busy`, `sheet_unavailable` | провайдер недоступен, занят или недоступны Google Таблицы |

## Как работает

1. **Вход.**
   - Текст — как есть.
   - Таблица — каждый лист превращается в сетку непустых ячеек `A1: значение`.
   - Из `.xlsx` берутся сохранённые значения формул; CSV — по RFC 4180, разделитель `,` или `;`.
   - Лимиты: 20 000 символов, файл до 1 МБ, до 10 листов, до 2 000 непустых ячеек.
2. **Google Таблица.**
   - Принимается только `https://docs.google.com/spreadsheets/d/{id}`. Адрес экспорта
     `…/export?format=csv&gid=…` сервер собирает сам.
   - Редиректы HTTP-клиент не выполняет: сервер проверяет каждый адрес и идёт только на HTTPS
     `docs.google.com` и `*.googleusercontent.com` (туда Google отдаёт CSV), не больше 3 переходов.
   - Ответ ограничен 1 МБ. Страница входа или редирект на `accounts.google.com` означают
     `sheet_not_accessible`.
3. **Модель** — `ProgramParserModel`, реализация DeepSeek. Вызывается вне транзакции БД, на виртуальном
   потоке, с таймаутом 60 с.
   - Общий `Semaphore` ограничивает одновременные вызовы на сервер (8); ждать места — до 20 с, иначе
     `import_busy`.
   - В модель уходят только текст программы и названия упражнений (каталог и свои). Имени, почты,
     1ПМ, профиля и травм в запросе нет.
4. **Ответ модели** — промежуточный JSON: вопросы или программа с упражнениями названиями и нагрузкой
   `percentOf1rm | rpe | weightKg | relativeToTopSet`. Его проверяет Bean Validation. Невалидный ответ —
   один повтор с ошибками в промпте, затем `model_output_invalid`. Сбой провайдера (сеть, 429, 5xx) —
   один повтор через 2 с, затем `import_unavailable`; 400/401/402/422 не повторяются.
5. **Вопросы.** До трёх раундов. В последнем модели велено не спрашивать, а принять допущения
   (они придут предупреждениями `assumption`).
6. **Сборка черновика** — детерминированно в коде (`DraftAssembler`):
   - упражнение — точное название → краткое название → триграммы `pg_trgm` (порог 0,6); не нашли —
     новое своё упражнение в `newExercises` и предупреждение `new_exercise` с похожими;
   - процент от 1ПМ → вес по 1ПМ владельца с округлением до 2,5 кг;
   - «−N% от топ-сета» — от посчитанного веса топ-сета;
   - RPE — в десятых с шагом 0,5;
   - даты недель — от `startDate`, дни 1–7;
   - id — UUID сервера; итог проверяется тем же Bean Validation, что и публикация.
7. **Сессия** (`import_session`) хранит вход, раунды, черновик и токены сутки; затем удаляется фоновой
   задачей.

## Модель и стоимость

Сверено с документацией DeepSeek (https://api-docs.deepseek.com, 22.10.2026):

- модель `deepseek-flash` — DeepSeek-V4.1-Flash. Имя `deepseek-v4-flash` из ADR — устаревший псевдоним,
  его запросы обслуживает та же V4.1-Flash. Имя модели задаётся `sizylift.imports.model.name`;
- цена за 1M токенов в часы пик: вход $0,30 (из кеша $0,006), выход $1,20; вне часов пик вдвое
  дешевле;
- JSON-режим — `response_format: {"type": "json_object"}`, в промпте есть слово «json» и пример формата;
  ответ может изредка прийти пустым — это обрабатывается как невалидный ответ;
- режим рассуждений по умолчанию включён, для разбора он выключается (`thinking: {"type": "disabled"}`);
- `POST https://api.deepseek.com/chat/completions`, `Authorization: Bearer $DEEPSEEK_API_KEY`.

Импорт программы — единицы тысяч токенов, около десятых долей цента.

## Конфигурация

`sizylift.imports.*` в `application.yaml`: лимиты, адрес и имя модели, таймауты. Ключ —
`sizylift.imports.model.api-key`: в `application-prod.yaml` это `${DEEPSEEK_API_KEY}` без значения по
умолчанию (проверяет `ProductionProfileTest`). Тесты используют заглушку DeepSeek
(`MockRestServiceServer`), реальных вызовов в CI нет.

## Метрики

- `sizylift.import.requests{source,outcome}` — `source`: `text`, `sheet_url`, `file`, `answers`;
  `outcome`: `questions`, `draft`, `failed`, `unavailable`, `rejected`;
- `sizylift.import.tokens{direction}` — `in`, `out`, по ответам модели;
- `sizylift.import.duration` — наблюдение (таймер и span `program import`) на раунд;
- `sizylift.import.rounds` — раундов вопросов до черновика.
