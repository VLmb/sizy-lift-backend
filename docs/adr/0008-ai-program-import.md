# ADR-0008: ИИ-импорт программ из текста и таблиц

Статус: предложено
Дата: 23 октября 2026
Основание: [ADR-0006](https://github.com/VLmb/sizy-lift-app/blob/main/docs/architecture/adr/0006-coach-and-athlete.md),
раздел «Импорт программ». Импорт с фото не делаем.

## Контекст

Пользователь вставляет программу текстом («присед 5×5 75%, жим 4×6 @8») или даёт Google
Таблицу / `.xlsx` / `.csv`. Нужно получить программу Sizy: недели, тренировки, упражнения
из каталога, подходы, веса, RPE. Если что-то неоднозначно, сначала задать вопросы с вариантами
ответа. Ничего не сохраняется без подтверждения.

## Решение коротко

- Модель — **DeepSeek V4 Flash** (`deepseek-v4-flash`) через OpenAI-совместимый Chat
  Completions API в режиме JSON-ответа. Вызов идёт только с сервера, ключ хранится только там.
- **Модель только понимает текст, всё остальное делает код.** Она выдаёт промежуточное
  описание. Сопоставление с каталогом, пересчёт процентов в веса и проверка делаются
  детерминированно на сервере.
- **Импорт — сессия из нескольких шагов** в PostgreSQL: вопросы → ответы → черновик.
- **Сервер программу не сохраняет.** Он возвращает черновик в формате payload `program` v1.
  Приложение показывает предпросмотр и сохраняет как обычную свою программу (дальше —
  обычная публикация или синхронизация). Веб — через свой API записи.

## 1. Технологии и почему

| Что                 | Выбор                                                     | Почему                                                                                                                                                                                                                       |
| ------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Модель              | DeepSeek V4 Flash                                         | Выбор владельца. Дёшево: по прайсу DeepSeek около $0,14 / 1M входных и $0,28 / 1M выходных токенов. Импорт программы — единицы тысяч токенов, то есть доли цента. Перед реализацией сверить имя модели и цену в консоли DeepSeek. |
| Клиент API          | Spring `RestClient` + свой тонкий клиент за интерфейсом `ProgramParserModel` | Один эндпоинт и JSON-режим; Spring AI 2.0 (совместим с Boot 4) добавил бы большой слой ради одного вызова. Интерфейс позволяет сменить провайдера (другая модель, свой сервер) без правок остального кода.           |
| Формат ответа модели | `response_format: json_object` + JSON Schema в промпте + Bean Validation на сервере | JSON-режим гарантирует синтаксис, валидация — смысл. Невалидный ответ — один повтор с ошибками в промпте, затем понятная ошибка пользователю.                                                                    |
| Таблицы `.xlsx`     | `org.dhatim:fastexcel-reader`                             | Потоковое чтение, маленькая библиотека. Берёт сохранённые значения формул, а именно они нужны: проценты и веса уже посчитаны в таблице. Apache POI тяжелее и для чтения значений избыточен.                                    |
| Таблицы `.csv`      | разбор на сервере (RFC 4180)                              | Без зависимостей.                                                                                                                                                                                                            |
| Google Таблицы      | экспорт `https://docs.google.com/spreadsheets/d/{id}/export?format=csv&gid={gid}` | Без OAuth-интеграции с Google. Работает для таблиц с доступом «по ссылке». Если доступа нет — понятная подсказка: открыть доступ или загрузить файл.                                                                |

## 2. Поток

```text
POST /api/v2/imports            { source: "text" | "sheet_url" | "file", text?, url?, file?, targetOwnerId? }
  → { id, status: "questions", questions: [...] }   или   { id, status: "draft", draft, warnings }
POST /api/v2/imports/{id}/answers   { answers: [{ questionId, optionId? , text? }] }
  → снова "questions" (редко) или "draft"
```

1. **Нормализация входа.** Текст — как есть. Таблица — каждый лист превращается в компактную
   сетку `A1: …` только с непустыми ячейками. Лимиты: 20 000 символов текста, файл до 1 МБ,
   до 10 листов, до 2 000 непустых ячеек.
2. **Первый вызов модели** — разбор. В промпте:
   - формат промежуточного описания (JSON Schema);
   - список упражнений каталога и своих упражнений пользователя (только названия и id;
     74 системных — около 2 тыс. токенов, кешируется провайдером как общий префикс);
   - правило: «если неоднозначно — не угадывай, верни вопрос с 2–4 вариантами».
3. **Модель возвращает** либо `questions`, либо `program` в промежуточном виде:
   упражнения названиями, нагрузка как `{ percentOf1rm | rpe | weightKg | relativeToTopSet }`.
4. **Вопросы и ответы** сохраняются в сессии. Второй вызов получает исходный текст, прежний
   ответ и ответы пользователя. Больше трёх раундов вопросов не делаем: дальше черновик
   с предупреждениями.
5. **Детерминированная сборка черновика:**
   - сопоставление упражнений: точное совпадение названия → синонимы каталога → нечёткое
     совпадение (триграммы `pg_trgm` по `exercise.name`, порог 0,6; расширение включается
     changeset'ом `CREATE EXTENSION pg_trgm`); не нашли — предупреждение
     «создать своё или выбрать похожее»;
   - процент от 1ПМ → вес по 1ПМ того, для кого программа: свой или подопечного при импорте
     тренером (право проверяет `AccessPolicy`, ADR-0007), округление до 2,5 кг; нет 1ПМ —
     процент остаётся в комментарии подхода, вес пустой;
   - «−10% от топ-сета» считается от уже посчитанного веса топ-сета;
   - даты недель — от выбранной даты старта;
   - проверка готового payload `program` v1 тем же Bean Validation, что при публикации.
6. **Ответ — черновик** с UUID для всех элементов, сгенерированными сервером, и списком
   предупреждений. Клиент показывает предпросмотр и сохраняет.

Модель не считает веса и не придумывает id. Это то, в чём LLM ошибаются чаще всего, поэтому
весь расчёт — на сервере и покрыт тестами.

## 3. Сессия импорта

```sql
CREATE TABLE sizylift.import_session (
    id              uuid        PRIMARY KEY,
    user_id         uuid        NOT NULL REFERENCES sizylift.user_account (id) ON DELETE CASCADE,
    target_owner_id uuid        NOT NULL,           -- для кого программа (сам или подопечный)
    source          text        NOT NULL CHECK (source IN ('text', 'sheet_url', 'file')),
    input           text        NOT NULL,           -- нормализованный вход
    status          text        NOT NULL CHECK (status IN ('questions', 'draft', 'failed')),
    rounds          jsonb       NOT NULL,           -- вопросы, ответы, сырой ответ модели по раундам
    draft           jsonb,
    tokens_in       integer     NOT NULL DEFAULT 0,
    tokens_out      integer     NOT NULL DEFAULT 0,
    created_at      timestamptz NOT NULL DEFAULT now(),
    expires_at      timestamptz NOT NULL            -- 24 часа, потом удаляется фоновой задачей
);
```

Сессия нужна, чтобы ответы на вопросы шли без повторной пересылки входа и чтобы считать
лимиты и стоимость. Она живёт сутки: это рабочий черновик, а не данные пользователя.

## 4. Надёжность и стоимость

- **Вызов модели вне транзакции БД.** Сессия пишется до вызова и после. Соединение из пула
  не держится 10–30 секунд ожидания.
- **Синхронный HTTP-запрос на виртуальном потоке** с таймаутом 60 с к модели. Ответ
  клиенту — когда готов, приложение показывает индикатор. Если p95 окажется больше 30 с,
  перейдём на асинхронный статус с опросом; API сессии это уже допускает.
- **Лимиты:** 20 импортов в сутки на пользователя (счёт по `import_session`), не больше
  2 одновременных. Сверх лимита — `429` с понятным текстом.
- **Повтор при сбое провайдера** — один, с паузой. Затем `503 import_unavailable`.
  Импорт — не критичная функция: дневник работает без неё.
- **Метрики:** `sizylift.import.requests{source,outcome}`,
  `sizylift.import.tokens{direction}`, `sizylift.import.duration`, число раундов вопросов.
  Стоимость видна в Grafana.

## 5. Безопасность и данные

- **В модель уходит только текст программы и названия упражнений.** Имени, почты, профиля
  и травм в запросе нет. 1ПМ в модель не уходит: проценты пересчитываются на сервере.
- **Провайдер — внешний сервис в Китае.** Это нужно указать в политике конфиденциальности.
  Интерфейс `ProgramParserModel` позволяет переключиться на другого провайдера
  или модель на своём сервере, если это станет требованием.
- **Подмена инструкций через текст** (prompt injection) безопасна: у модели нет инструментов
  и доступа к данным, а её ответ — только данные, которые проверяет код.
- **Защита от SSRF при импорте по ссылке:** принимается только `docs.google.com/spreadsheets/d/{id}`.
  URL экспорта собирается сервером из извлечённого `id` и `gid`, редиректы на другие хосты
  не выполняются, размер ответа ограничен.
- Ключ — переменная окружения `DEEPSEEK_API_KEY` в prod-профиле, без значения по умолчанию
  (как остальные секреты, проверяется `ProductionProfileTest`).

## 6. Проверки

- Юнит-тесты детерминированной сборки: проценты, «−10% от топ-сета», округление, даты,
  сопоставление упражнений.
- Интеграционные тесты API с заглушкой модели (`MockRestServiceServer`): вопросы → ответы
  → черновик, невалидный JSON → повтор → ошибка, лимиты.
- **Эталонный набор** из 20–30 реальных программ (текст и таблицы) с ожидаемым результатом.
  Прогоняется против настоящей модели вручную, перед сменой модели или промпта; в CI не входит,
  потому что платно и недетерминированно. Метрика — доля программ, собранных без правок.

## Рассмотрено и отклонено

- **Модель с распознаванием изображений для фото** — отложено владельцем, дороже.
- **Spring AI** — лишний слой ради одного вызова; можно перейти позже, если вызовов станет больше.
- **Вызов модели из приложения** — ключ оказался бы в приложении.
- **Модель считает веса сама** — ошибки арифметики и округления; детерминированный код надёжнее.
- **OAuth к Google Drive** — сложная настройка ради одного сценария; экспорт по ссылке
  и загрузка файла покрывают его.
