# ADR-0008: AI-импорт программ из текста и таблиц

Статус: принято; сервер реализован, веб-интерфейс — отдельная задача.

## Решение

Пользователь загружает текст, XLS/XLSX/CSV или ссылку на публичную Google Таблицу.
Backend извлекает значения и координаты; произвольную структуру программы понимает DeepSeek.
В один основной запрос отправляются источник и доступный каталог **только id + название**.
Модель `deepseek-flash`, thinking выключен; strict tool calling возвращает `ImportDraftV1`.

Если смысл источника неясен, модель возвращает `needsClarification` и сообщение с вопросом.
Пользователь отвечает свободным текстом. Контекст хранится в PostgreSQL отдельно по importId:
исходник, снимок каталога, актуальный черновик и все вопросы/ответы. Каждый следующий запрос
DeepSeek получает этот контекст заново. Максимум три раунда уточнений.

Выбор упражнения — отдельный интерфейс: matched, ambiguous, new. Пользователь может выбрать
существующее упражнение через поиск либо подготовить своё. Никакие библиотечные записи
не создаются до финального commit. Других структурированных типов вопросов пользователю нет.

Backend валидирует схему, ID, ссылки на источник, значения и доменный payload; преобразует
единицы и назначает стабильные UUID. Неизвестное остаётся неизвестным, без defaultSet/auto-RPE.
Диапазоны повторений и RIR сохраняются в заметках до расширения моделей.

Сессия и worker — в модульном монолите: PostgreSQL, SKIP LOCKED, аренда и fencing token.
Вызов модели выполняется вне транзакции. Технический повтор ограничен бюджетом и одной попыткой.
Общий commit создаёт упражнения и программу-черновик через существующую sync-логику;
права, копирование упражнений тренера, ленты и уведомления сохраняют штатное поведение.
Вся операция с квитанцией идемпотентности атомарна.

Используются Spring AI DeepSeek 2.0.2, Apache POI 6.0.0, Commons CSV 1.14.1 и networknt 3.0.8.
API, ограничения, конфигурация, схема и проверки — [imports.md](../imports.md).
