# ADR-0009: Push-уведомления

Статус: предложено
Дата: 23 октября 2026
Основание: [ADR-0006](https://github.com/VLmb/sizy-lift-app/blob/main/docs/architecture/adr/0006-coach-and-athlete.md),
раздел «Уведомления»; [ADR-0007](0007-two-way-sync-and-coaching.md) — лента изменений.

## Контекст

Уведомлять нужно немного:

- **подопечного** — о новой или изменённой программе, о комментарии тренера;
- **тренера** — что подопечный завершил тренировку, оставил комментарий, перенёс тренировку,
  принял приглашение.

Кроме того, push служит сигналом «подтяни ленту изменений», чтобы данные приходили
без открытия приложения.

## Решение коротко

- **Expo Push Service** через его HTTP API, вызов с сервера `RestClient`.
- **Транзакционный outbox уведомлений** в PostgreSQL: событие ставится в той же транзакции,
  что и изменение данных, а отправляет его фоновая задача.
- **В уведомлении нет данных пользователя**, только тип и идентификаторы. Содержимое
  приложение берёт из ленты.

## 1. Технологии и почему

| Что                | Выбор                                   | Почему                                                                                                                                                                                                  |
| ------------------ | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Провайдер          | Expo Push Service (`exp.host/--/api/v2/push/send`) | Приложение на Expo. Один API для iOS и Android, ключи APNs и FCM хранит Expo. Не нужно держать на сервере два SDK и сертификаты. Переход на прямые APNs/FCM возможен: токены устройств — отдельная таблица. |
| Клиент             | Spring `RestClient`                     | Готового официального Java SDK нет. API — POST с JSON-массивом, пачки по 100 сообщений.                                                                                                                       |
| Очередь            | таблица + `@Scheduled` + `FOR UPDATE SKIP LOCKED` | Как в ADR-0007: без брокера; атомарно с изменением данных; переживает рестарт.                                                                                                                         |

## 2. Устройства

```sql
CREATE TABLE sizylift.device (
    id           uuid        PRIMARY KEY,          -- id установки, генерирует приложение; он же clientId в ADR-0007
    user_id      uuid        NOT NULL REFERENCES sizylift.user_account (id) ON DELETE CASCADE,
    platform     text        NOT NULL CHECK (platform IN ('ios', 'android')),
    push_token   text,                             -- ExponentPushToken[…]; NULL — уведомления запрещены
    last_seen_at timestamptz NOT NULL DEFAULT now()
);
```

- Приложение регистрирует устройство после входа и при смене токена:
  `PUT /api/v2/devices/{id}`.
- При выходе из аккаунта токен удаляется.
- Токен, на который Expo ответил `DeviceNotRegistered`, обнуляется.

## 3. Outbox и отправка

```sql
CREATE TABLE sizylift.notification_outbox (
    id              uuid        PRIMARY KEY,
    user_id         uuid        NOT NULL,          -- получатель
    kind            text        NOT NULL,          -- program_updated, comment_added, workout_completed, …
    data            jsonb       NOT NULL,          -- только id: { "ownerId": …, "aggregateId": … }
    created_at      timestamptz NOT NULL DEFAULT now(),
    attempts        integer     NOT NULL DEFAULT 0,
    next_attempt_at timestamptz NOT NULL DEFAULT now(),
    sent_at         timestamptz,
    ticket_ids      jsonb                          -- для проверки квитанций
);
```

1. **Постановка.** Сервис, который меняет данные (`ADR-0007`: запись программы тренером,
   комментарий, принятие приглашения), в той же транзакции добавляет строку в outbox.
   Нет коммита — нет уведомления. Есть коммит — уведомление не потеряется при падении
   процесса.
2. **Отправка.** Задача раз в 5 с:
   - берёт до 100 строк `WHERE sent_at IS NULL AND next_attempt_at <= now() FOR UPDATE SKIP LOCKED`;
   - собирает сообщения на все устройства получателей с токеном и шлёт их пачкой;
   - записывает `ticket_ids`.

   Ошибка сети или 5xx — повтор с экспоненциальной паузой (до 6 попыток), затем строка
   остаётся неотправленной. Это видно в метрике.
3. **Квитанции.** Задача раз в 15 минут запрашивает квитанции по тикетам старше 15 минут
   (Expo хранит их около суток). `DeviceNotRegistered` → обнулить токен. Остальные ошибки
   → метрика.
4. **Склейка.** Если у получателя в очереди уже есть неотправленное уведомление того же вида
   по тому же агрегату, второе не ставится. Тренер, нажавший «Скорректировать» трижды
   за минуту, даёт одно уведомление.
5. **Очистка.** Отправленные строки старше 7 дней удаляются.

## 4. Содержимое

- Заголовок и текст общие, без данных: «Тренер обновил программу», «Новый комментарий
  к тренировке», «Иван завершил тренировку». Имя второй стороны допустимо: это тот, кого
  пользователь сам добавил. Названий упражнений, весов и текста комментария нет. Экран
  блокировки видят посторонние.
- `data` — тип и id для перехода на нужный экран. Получив уведомление, приложение подтягивает
  ленту (ADR-0007) и только потом открывает экран.
- Неотправленный или потерянный push не ломает данные: лента дочитается при следующем
  открытии приложения. Push — ускоритель, а не канал доставки.

## 5. Конфигурация и проверки

- Access token Expo (включена защита отправки) — переменная окружения `EXPO_ACCESS_TOKEN`
  в prod без значения по умолчанию.
- В dev и в тестах отправка идёт в заглушку (`sizylift.notifications.enabled=false`):
  строки копятся в outbox, тесты проверяют их состав.
- Тесты: уведомление ставится только при коммите; склейка; повтор и разбор ответов Expo
  через `MockRestServiceServer`; `DeviceNotRegistered` обнуляет токен.
- Метрики: `sizylift.notifications.sent{kind,outcome}`, размер очереди, возраст самой
  старой неотправленной строки.

## Рассмотрено и отклонено

- **Прямые APNs и FCM** — два SDK, сертификаты и ключи на сервере. Expo закрывает это
  для Expo-приложения; переход возможен позже.
- **Отправка прямо из сервиса в момент изменения** — уведомление о данных, которые потом
  откатились, или потерянное уведомление при падении между коммитом и отправкой.
- **Данные в теле push** — утечка на экран блокировки и рассинхрон с лентой.
- **Telegram-бот как канал уведомлений** — позже, если попросят (ADR-0006).
