# Тема и согласие Sizy в Keycloak

Тема `keycloak/themes/sizy` воспроизводит согласованный HTML-макет приложения:
палитра «Бронза», DIN 2014, знак Sizy, поля и кнопки высотой 48 px, радиус 8 px,
адаптация для телефона и компьютера. Тема наследует `keycloak.v2` **26.8.1**:
штатные действия форм, проверка почты, пароля, восстановление, сообщения ошибок,
выбор языка и внешние провайдеры остаются у Keycloak. Собственные шаблоны
`login.ftl` и `register.ftl` основаны на версии 26.8.1; при обновлении сверить их
с upstream. В регистрации проверка пароля на клиенте подключается только когда
есть его поле (в email-first регистрации поля ещё нет).

## Сборка и существующий realm

```bash
./gradlew :keycloak-provider:jar
docker compose up -d --wait
```

Local Compose монтирует тему и собранный JAR. Отсутствующий JAR выдаёт ошибку
bind mount, а не создаёт каталог. В production тема и провайдер копируются в образ
до `kc.sh build`. `./gradlew bootJar` также собирает провайдер, `./gradlew build`
проверяет backend с настоящими PostgreSQL/Keycloak. Провайдер компилируется для
Java 21, используемой Keycloak; сам backend продолжает использовать Java 25.

Для **нового** realm тема, flow и required action импортируются из
`keycloak/realm-sizylift.json`. Для **существующего** realm повторный импорт при
старте не срабатывает. Для одного оформления достаточно выбрать
**Realm settings → Themes → Login theme → sizy** после обновления образа.
Не удалять production realm или тома ради темы.

## Согласие пока выключено

Владелец 26.10.2026 отложил оформление оставшихся реквизитов в backlog.
По умолчанию `SIZY_CONSENT_ENABLED=false`: галочки и required action согласия нет,
пустые проекты документов не публикуются и не выдаются за действующую политику.
Рабочая синхронизация и её основания этим изменением не исправляются.

Проекты политики/согласия с оператором **Ламбатов Владимир Иванович**, контактом
**@vvv_lmb**, а также исследование находятся в
[репозитории приложения](https://github.com/VLmb/sizy-lift-app/tree/main/design/prototypes/auth).
Задача дооформления — в [backlog](backlog.md). Не включать сбор согласия до решения
здоровья: проект обычного согласия исключает травмы/противопоказания, которые сейчас
синхронизируются. Существующие токены/refresh sessions и API также нуждаются в
согласованном механизме прекращения обработки при отзыве; одно браузерное действие
не является контролем всех серверных операций.

## Подготовленный механизм включения

После завершения юридической задачи:

1. Опубликовать утверждённые отдельные документы на публичных HTTPS URL без
   авторизации и фрагментов. Содержимое версии не менять; хранить прежние версии.
2. Для нового realm задать переменные из `.env.example`:
   `SIZY_CONSENT_ENABLED=true`, `SIZY_CONSENT_VERSION` (1–80 латинских букв, цифр,
   точек, дефисов или подчёркиваний), `SIZY_PRIVACY_URL`, `SIZY_CONSENT_URL`.
   Значения в Compose используются при первом импорте.
3. В существующем realm задать атрибуты `sizy.legal.enabled=true`,
   `sizy.legal.version`, `sizy.legal.privacy-url`, `sizy.legal.consent-url`.
   Переменные окружения не обновляют существующий realm.
4. В **Authentication → Required actions → Register** зарегистрировать провайдер
   **Sizy account consent** (`sizy-account-consent`) и включить его. Default action
   не нужен: провайдер сам проверяет запись при браузерной аутентификации.
5. Создать копию registration flow. Сохранить встроенные user creation и password
   validation, добавить **Sizy account consent** (`sizy-registration-consent`)
   как Required после создания пользователя; назначить flow в Bindings.
   Точная структура нового flow — в realm-файле. Проверить действующие reCAPTCHA
   и иные локальные настройки, сохранив их при копировании.
   В **Realm settings → User profile** добавить многозначный атрибут
   `sizy_account_consent` с view/edit только для **admin**, без permissions user.
   Это служебное поле не показывается и не редактируется в пользовательских формах.
6. Проверить регистрацию, email → пароль, старый аккаунт, SSO, включённые IdP,
   отмену и смену версии, а также принятое отдельное решение для API/здоровья/отзыва.

Неполная конфигурация при включённом согласии блокирует регистрацию/подтверждение
с сообщением об ошибке. HTTP, `javascript:` и URL с credentials/фрагментом
не принимаются. В формах ссылки открываются отдельно с `noopener noreferrer`,
контекст сессии и введённые значения не попадают в адрес документа.

## Что проверяется и сохраняется

`RegistrationConsent` проверяет на сервере **значение** `termsAccepted=on`:
отсутствующее поле или `false` не подходят. Хеш версии и обоих URL запоминается в
authentication session при показе. Изменение конфигурации между показом и POST
требует прочитать документ заново. Скрытые поля клиента не задают версию.

После успешной проверки пользователь создаётся штатным FormAction, а запись
согласия сохраняется в той же транзакции Keycloak. В служебный многозначный
атрибут `sizy_account_consent` добавляется JSON: хеш конфигурации (версия и URL),
версия, UTC-время, URL политики и согласия. Прежние записи сохраняются, уже
существующая запись не обновляется при повторном входе. В новом realm атрибут
доступен только администратору; не разрешать его редактирование пользователем
через User Profile, Account Console или IdP mapping и не включать в токены.

`ConsentRequiredAction` при новом браузерном входе (включая SSO/IdP) запрашивает
согласие при отсутствии актуальной записи; POST без галочки не выдаёт code/токены.
Отмена завершает авторизацию ошибкой. Отключение настройки не создаёт фиктивной записи.

Это запись в БД Keycloak, **не отдельный неизменяемый юридический архив**:
администратор может изменить атрибуты, удаление пользователя удаляет записи.
Долговременный журнал доказательств, отзыв, сроки хранения и защита служебных
атрибутов должны быть согласованы в задаче юридического включения. Текст документов
хранится по версионированным URL; JAR не публикует черновики из HTML-макета.

[FormAction / RequiredAction SPI](https://www.keycloak.org/docs/latest/server_development/#_auth_spi),
[исходники 26.8.1](https://github.com/keycloak/keycloak/tree/26.8.1/themes/src/main/resources/theme/keycloak.v2/login).
