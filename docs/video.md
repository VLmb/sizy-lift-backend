# Видео подходов и техники

Контракт видео из переделки тренерского режима, этап 3 (CR-14–CR-16). Решения и обоснования —
[ADR-0012](adr/0012-video-storage.md); комментарий к упражнению — [coaching.md](coaching.md#комментарии).

Загружает видео только приложение (iOS, Android); смотрят все клиенты. Файлы идут мимо сервера, по
подписанным ссылкам прямо в хранилище. Фото тренировок по-прежнему не публикуются.

## Ролик

| Поле | Описание |
| --- | --- |
| `id` | uuid, придумывает приложение: комментарий ссылается на ролик раньше, чем появляется сеть |
| `ownerId` | владелец — кто загрузил |
| `kind` | `set` — видео подхода, `technique` — видео техники тренера |
| `status` | `pending` — место выдано, загрузка не подтверждена; `ready` — можно смотреть |
| `sizeBytes`, `durationMs` | размер ролика и длина |
| `title` | название видео техники (обязательно для `technique`, у `set` всегда `null`) |
| `exerciseId`, `exerciseName` | упражнение, к которому снят ролик; название — как его видел владелец при загрузке |
| `createdAt`, `uploadedAt` | выдача места и подтверждение загрузки |
| `videoUrl`, `previewUrl`, `urlExpiresAt` | подписанные ссылки GET и срок их действия; только у `ready` |
| `usage` | где ролик используется; только владельцу, остальным `null` |

`usage`:

```json
{ "comments": [ { "commentId": "…", "ownerId": "…", "workoutId": "…", "workoutDate": "2026-11-11",
                  "workoutExerciseId": "…", "setNumber": 5 } ],
  "programs": [ { "programId": "…", "ownerId": "…", "name": "Силовой блок" } ] }
```

- `comments` — комментарии к упражнениям с этим роликом, по времени. `workoutDate` — `null`, пока тренировка
  не опубликована. По `workoutId` клиент открывает тренировку.
- `programs` — программы, в упражнениях которых ролик прикреплён: свои и действующих подопечных, по названию.
  `ownerId` — в чьём пространстве программа.

Ключи объектов производные (`video/{ownerId}/{id}.mp4` и `.jpg`), в ответах, логах и телеметрии их нет.

## Пределы

Настройки `sizylift.video.*` (`application.yaml`), не константы.

| Что | Значение | Отказ |
| --- | --- | --- |
| Ролик | 25 МБ, 60 с | 422 `video_too_large`, 422 `video_too_long` |
| Кадр-превью | 200 КБ | 422 `video_too_large` |
| Квота пользователя | 300 МБ на `set`, 1 ГБ на `technique` | 409 `quota_exceeded` |
| Всё хранилище | 8 ГБ | 503 `storage_full` |

В квоту входят ролики и превью, включая незавершённые загрузки. Срока хранения нет. Формат сервер глубже
типа содержимого и размера не проверяет.

Ошибки — `{ "code": "…", "message": "…" }`. Остальные коды: 400 `invalid_video`, 403 `coach_required`
(видео техники загружает только аккаунт с включённым режимом тренера), 404 `not_found`, 409 `id_conflict`,
409 `upload_incomplete`.

## API `/api/v2/videos`

### `POST /api/v2/videos` — место под ролик

```json
{ "id": "…", "kind": "set", "sizeBytes": 12400000, "previewSizeBytes": 84000, "durationMs": 24000,
  "title": null, "exerciseId": "…", "exerciseName": "Присед со штангой" }
```

Ответ 200:

```json
{ "video": { "id": "…", "status": "pending", "…": "…" },
  "upload": { "videoUrl": "…", "videoContentType": "video/mp4",
              "previewUrl": "…", "previewContentType": "image/jpeg", "expiresAt": "…" } }
```

- Ссылки PUT живут 15 минут. В подпись входят `Content-Type` и точный размер тела: другой тип или размер
  хранилище отклоняет (403). Файл кладётся одним запросом PUT с заголовком `Content-Type` из ответа.
- Повтор с тем же `id`, видом и размерами до подтверждения загрузки возвращает новые ссылки и квоту второй
  раз не тратит — так приложение повторяет загрузку после обрыва. Для уже загруженного ролика `upload` —
  `null`. Чужой `id` или другие размеры — 409 `id_conflict`.

### `POST /api/v2/videos/{id}/complete` — загрузка завершена

Сервер проверяет, что оба объекта есть и их размер совпадает с заявленным, и переводит ролик в `ready`.
Ответ — ролик со ссылками. Объектов нет или размер другой — 409 `upload_incomplete`. Повтор для готового
ролика возвращает его же. Только владелец.

Незавершённые загрузки старше суток ежедневная задача удаляет вместе с объектами.

### `GET /api/v2/videos/{id}` — сведения и ссылки на просмотр

Ссылки GET живут 10 минут; хранилище отвечает на запросы `Range` (206), ролик играет до полной загрузки.
У `pending` ссылок нет: клиент показывает «Видео загружается». Ролика нет, он чужой или недоступен — 404
(в том числе пока приложение не запросило место: комментарий со ссылкой на видео приходит раньше).

### `GET /api/v2/videos?kind=set|technique&cursor=&limit=` — свои ролики

Раздел «Видео»: ролики, загруженные самим пользователем, новые сначала. `limit` — 1…100, по умолчанию 30.

```json
{ "videos": [ { "…": "…", "previewUrl": "…", "videoUrl": null, "usage": { "…": "…" } } ],
  "nextCursor": null, "quota": { "usedBytes": 37200000, "limitBytes": 314572800 } }
```

В списке приходят только ссылки на превью; ролик открывается через `GET /api/v2/videos/{id}`. У подопечного
упражнение — `exerciseName`, дата — `usage.comments[0].workoutDate` (нет — `createdAt`), номер подхода —
`usage.comments[0].setNumber`, тренировка — `usage.comments[0].workoutId`. У тренера «где используется» —
`usage.programs`. Чужих роликов в списке нет: видео подопечных тренер смотрит в тренировках.

### `DELETE /api/v2/videos/{id}` — удалить

Только владелец. Ответ 200:

```json
{ "id": "…", "removedFrom": { "comments": [ … ], "programs": [ … ] } }
```

- Ролик снимается со всех комментариев и программ. Комментарий теряет `videoId` и `videoDurationMs`;
  комментарий без текста удаляется. У упражнений программ — своих, действующих и бывших подопечных —
  пропадает `techniqueVideoId`. Каждый затронутый агрегат получает новую ревизию и расходится по лентам
  (`upsert` или `delete`), как каскады сервера; push об этом не отправляется.
- `removedFrom` — то же, что `usage` до удаления: клиент спрашивает подтверждение по `usage` из списка или
  `GET`, а ответ удаления сообщает, откуда ролик убран на самом деле.
- Файлы удаляет фоновая задача (очередь `video_removal`, раз в минуту); при сбое хранилища повторяет.

## Доступ

| Видео | Видит | Загружает и удаляет |
| --- | --- | --- |
| `set` | владелец и его действующий тренер | владелец |
| `technique` | тренер-владелец и действующий подопечный, в чьей программе оно прикреплено | тренер-владелец |

После разрыва связи тренер получает 404 на видео подопечного, подопечный — на видео техники тренера;
`techniqueVideoId` в его программах остаётся, клиент скрывает кнопку по 404. Файлы при разрыве не
удаляются. Удаление аккаунта удаляет его ролики и файлы.

## Комментарий к упражнению и программа

- `workout_comment`: необязательные `workoutExerciseId`, `setNumber`, `videoId`, `videoDurationMs` —
  [coaching.md](coaching.md#комментарии).
- Программа: у упражнения необязательное `techniqueVideoId` — видео техники тренера. Хранится в
  `planned_exercise.technique_video_id`, копируется вместе с программой (назначение нескольким, приглашение
  с программой). Сервер не проверяет, что ролик существует: доступ решается при просмотре.
- Ни комментарий, ни программа не ждут загрузки ролика: в синхронизацию попадает только id.

## Хранилище

Garage v2.5.0 в отдельном контейнере, один узел (`deploy/garage/garage.toml`); сервер работает с ним только
через S3 API (AWS SDK). Смена хранилища — адрес и ключи в `sizylift.video.storage.*` и копирование бакета.
`endpoint` — адрес для сервера, `public-endpoint` — адрес в подписанных ссылках (в production —
`https://<MEDIA_DOMAIN>` через Caddy). Узел, ключ и закрытый бакет создаются при первом запуске контейнера
(`--single-node --default-bucket`).

Проверка Garage (ADR-0012, раздел 9) — `VideoApiTest` на том же образе в Testcontainers: подписанные PUT
с типом и размером в подписи, подписанные GET, `Range` → 206 с `Content-Range`, анонимный запрос → 403.
Квота бакета Garage (`garage bucket set-quotas`) работает, но общий предел считает сервер по таблице
`video` — так он не зависит от хранилища.

## Таблицы (changeset `036-video`)

- `video` — запись о ролике.
- `video_removal` — очередь удаления файлов.
- `workout_comment`: `workout_exercise_id`, `set_number`, `video_id`, `video_duration_ms`.
- `planned_exercise.technique_video_id`.

## Метрики

- `sizylift.video.stored.bytes` — занято роликами и превью; `sizylift.video.bucket.limit.bytes` — предел.
- `sizylift.video.removal.failures` — сбои удаления файлов из хранилища.
