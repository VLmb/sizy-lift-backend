# Архитектура

Сервер находится в отдельном репозитории `VLmb/sizy-lift-backend`. Это уточняет
первоначальное размещение `apps/server` из ADR-0004 мобильного репозитория.

## Принятые решения

- Java 25, Spring Boot, Gradle Wrapper с Kotlin DSL.
- Модульный монолит, Spring MVC, PostgreSQL, Liquibase с SQL changeset-файлами.
- Организация package by feature: будущие `identity`, `publication`, `workouts`.
  Внутри feature — `api`, `application`, `domain`, `infrastructure`. Пустые слои
  заранее не создаются. Hibernate проверяет схему; изменяет её только Liquibase.
- Версионируемый REST API (`/api/v1`) для мобильного клиента.
- Первый обмен данными — контролируемая односторонняя публикация из локальной
  SQLite: outbox, пакетная отправка, стабильные идентификаторы операций,
  идемпотентное применение и подтверждение сервером. Kafka сейчас не требуется.
- Полная синхронизация нескольких устройств и разрешение конфликтов — отдельный этап.

## Аутентификация: согласована, реализация следующим этапом

Keycloak управляет регистрацией через email/пароль, подтверждением почты,
восстановлением доступа и входом через Google/Facebook. Spring Security будет
проверять access token; собственный профиль связан с внешней идентичностью
по `issuer` и `sub`. Мобильный клиент использует системный браузер и
Authorization Code + PKCE, секреты провайдеров не попадают в клиент.

Текущая инициализация не содержит Keycloak realm, OAuth-клиентов, регистрации,
токенов, таблиц пользователей или защищённых бизнес-методов. Keycloak и его
отдельное хранилище добавляются вместе с реализацией аутентификации. Открыт
только технический health endpoint; публичное production-развёртывание не настроено.
